# MOSAIC: Multi-Objective Search for Allocating Inference Cache Across LLM Decoder Layers

Code and results for the paper. MOSAIC learns per-layer KV-cache budgets for a token-eviction method with one
multi-objective search per task, transfers the result to every target budget, and optionally refines it per budget.

```
MOSAIC/
├── nas/                  the search pipeline (Stages 1-4) and the EvolKV-style baseline
├── pyramidkv/            KV-cache eviction implementations (SnapKV, H2O, AdaKV, L2Norm, ...), patched into HF models
├── results/cells.csv     every cell reported in the paper, with the per-layer allocations behind it
├── scripts/              verify_paper_numbers.py
├── tests/                decoder invariants and a GPU-free smoke test of the search loop
└── requirements.txt
```

## Reproduce the paper's numbers from the released results (no GPU)

```bash
python scripts/verify_paper_numbers.py      # recomputes the headline counts from results/cells.csv and checks them
python tests/test_decoder.py                # budget decoder: exact mean, floor and cap respected
python tests/test_search_toy.py             # search loop end to end on a synthetic objective (~30 s)
```

`results/cells.csv` has one row per (model, method, benchmark, task, budget) that appears in the paper (175 rows;
154 have a Stage 4 search, 21 have only the rescaled Winner or, for Mistral Summarization, only uniform allocation).

| column | meaning |
|---|---|
| `model`, `method`, `benchmark`, `task`, `budget` | the cell; `budget` is the average per-layer budget `B` |
| `stage4_search` | 1 if a budget-constrained search ran for this cell |
| `per_layer_floor` | minimum per-layer budget used when decoding (16 or 64) |
| `uniform` | score of uniform allocation at `B` (full data) |
| `winner` | Stage 3: the Stage 2 winner rescaled to `B` |
| `nas_refined` | Stage 4: best candidate of the search, excluding uniform and the Winner |
| `mosaic`, `mosaic_config` | the better of `winner` and `nas_refined`, and which one it is |
| `winner_allocation`, `nas_refined_allocation` | 32 per-layer budgets (space separated; mean = `B`) |
| `uniform_subscores`, `mosaic_subscores` | per-dataset (LongBench) or per-subtask (RULER) scores, `name=score;...`, where recorded |

Scores are full-data task scores: the mean over a category's datasets for LongBench, string-match accuracy averaged
over 11 subtasks for RULER. Rows without `mosaic` (Mistral Summarization) have only the uniform score.

## Setup

```bash
pip install -r requirements.txt
```

* **Models:** `meta-llama/Meta-Llama-3-8B-Instruct`, `mistralai/Mistral-7B-Instruct-v0.2`. Set `NAS_MODEL_PATH` to a local
  path or a Hugging Face id.
* **Data:** place LongBench (official release, one `<dataset>.jsonl` per dataset) in `data/LongBench/`, and RULER
  generated with its official code at 4096 tokens (500 samples per subtask, `data/RULER/4096/<subtask>.jsonl`).
  Override with `NAS_DATA_DIR`.
* **Python path:** every script is run from `nas/` with the repository root on `PYTHONPATH`
  (`export PYTHONPATH=$PWD:$PYTHONPATH` from the repository root). The launchers set it themselves.
* Method names are lowercase and exact: `snapkv`, `h2o`, `adakv`, `l2norm`. The attention implementation defaults to FlashAttention-2 (`NAS_ATTN_IMPL`).
* Scores of the same configuration can differ slightly between machines and torch versions, most visibly for AdaKV,
  so evaluate all methods of one comparison on one machine.

## Running the pipeline

All search runs write to `nas/<TASK>/<method>/output.txt` (one row per evaluated allocation: 32 layer weights, average
budget, negative score). Calibration subsets are drawn with a fixed seed (`NAS_SEED`, default 42).
LongBench task groups: `SINGLE_DOCUMENT_QA`, `MULTI_DOCUMENT_QA`, `CODE`, `SUMMARIZATION`; RULER: `RULER_ALL`.

**Stage 1, unconstrained search** (one per task and method). The paper uses a 30% calibration subset on LongBench and
10% on RULER; the launchers' defaults differ, so pass the ratio explicitly:

```bash
# LongBench
NAS_METHOD=snapkv NAS_TASK_CATEGORY=SINGLE_DOCUMENT_QA NAS_SAMPLE_RATIO=0.3 NAS_MODEL_PATH=<model> bash nas/run_nas.sh
# RULER (3-GPU worker pool by default: NAS_GPUS=0,1,2)
NAS_METHOD=snapkv NAS_TASK_CATEGORY=RULER_ALL NAS_SAMPLE_RATIO=0.1 NAS_MODEL_PATH=<model> bash nas/run_nas_ruler.sh
```

**Stage 2, winner selection.** Re-evaluate the Pareto front on full data, then keep the best shaped (non-uniform)
configuration as the anchor:

```bash
cd nas
python eval_top_configs_longbench.py SINGLE_DOCUMENT_QA --method snapkv --sample_ratio 1.0   # RULER: eval_top_configs_ruler.py RULER_ALL ...
python extract_winner_from_eval.py SINGLE_DOCUMENT_QA/snapkv/top_configs/eval_results.csv --out anchors/anchor_longbench_SINGLE_DOCUMENT_QA_snapkv.txt
```

**Stage 3, rescale the winner to fixed budgets** (no search; evaluates the rescaled winner and uniform on full data):

```bash
python eval_fixed_budgets_from_anchor.py anchors/anchor_longbench_SINGLE_DOCUMENT_QA_snapkv.txt --method snapkv \
    --benchmark longbench --base_category SINGLE_DOCUMENT_QA --targets 128,256,512,1024 --gpu 0
```

**Stage 4, budget-constrained search** (seeded with uniform, five heuristic shapes, the rescaled Winner and 57 Latin
hypercube points; 10% calibration), then full-data evaluation of its best candidates:

```bash
NAS_METHOD=snapkv bash run_nas_longbench_slices.sh        # RULER: NAS_ANCHOR_FILE=anchors/anchor_1756_budgets.txt NAS_METHOD=snapkv bash run_nas_ruler_slices.sh
NAS_BENCHMARK=longbench NAS_TASK_CATEGORY=SINGLE_DOCUMENT_QA_B512 NAS_METHOD=snapkv NAS_TARGET_BUDGET=512 bash run_5way_eval.sh
```

`nas/anchors/` holds the Stage 2 anchors that seeded the Llama-3-8B SnapKV and H2O searches in the paper
(`anchor_longbench_<TASK>_<method>.txt`; RULER: `anchor_1756_budgets.txt` for SnapKV, `anchor_h2o_2180.txt` for H2O).
Each script's header comment documents its arguments.

**Baseline.** `nas/run_grouped_cmaes.py`, `run_evolkv_reproduction.py`, `eval_evolkv_expansion.py` and
`eval_evolkv_repro_full_data.py` reproduce the EvolKV-style comparison (grouped CMA-ES, 8-layer groups, budget
completion rule).

## What the search does

`nas/LAMP.py` runs the guided search: non-dominated sorting of the archive, an MLP classifier trained to separate
rank-1 configurations from the rest, and differential evolution to propose the next configuration. `nas/HFF_mod.py`
wires it to the objective (`run_longbench_lamp.py`, `run_ruler_lamp.py`: average budget and task score on the
calibration subset). Continuous weights are decoded to integer budgets with the exact target mean in
`x_point_to_budgets_continuous` (floor and cap enforced, remainder redistributed in proportion to the weights).
